# 概要

最終更新: 2026-08-12

## これは何か

**macOS の既定ブラウザとして自分を登録し、受け取った URL を判断して本物のブラウザへ受け渡す常駐アプリ。**
Velja が近い。

メールや Discord から来るリンクは、行き先ごとに開きたいブラウザが違う。
大学関係は Safari、開発関係は Chrome、検証は Chrome Canary。
これまでは既定ブラウザで開いてから URL をコピーして貼り直していた。その手間をなくす。

## 動き

```
Discord / メール / ターミナル
        │  クリック（http, https）
        ▼
   Ferry.app  ← 既定ブラウザとして登録されている
        │
        ├ 1. 前処理     短縮URL展開 → トラッキングパラメータ除去
        ├ 2. 修飾キー   option を押していればルールを飛ばす
        ├ 3. ルール照合 上から順に、最初に当たったものを採用
        │       一致 ─────────────┐
        │       不一致 → 選択パネル ─┤
        ▼                          ▼
   選ばれたブラウザで開く
```

## 設計の中心

**Ferry は URL を自分で表示しない。** 受け取って、加工して、別のアプリへ渡すだけの中継役に徹する。
Web ビューも履歴のデータベースも持たない。

もう1つは **リンクが開けなくなる事態を作らないこと**。既定ブラウザを乗っ取る以上、
Ferry が壊れるとすべてのリンクが死ぬ。そのため次の3つを最初から入れてある。

- メニューバーの**一時停止**（ルールもパネルも通さず設定ブラウザへ直接流す）
- **設定ブラウザ**（一時停止中の行き先。ルールの指すブラウザが消えていたときもここへ）
- 既定ブラウザを切り替える前に**元の既定を控え、戻すボタンを出す**

## 何をしないか

- 送信元アプリごとの分岐（Discord からは Chrome、など）はまだ無い。→ history.md の「今後」
- Chrome のプロファイル指定はまだ無い
- URL をブラウザ以外のアプリで開く（x.com → X.app）はまだ無い
